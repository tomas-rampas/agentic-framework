# Developing the agentic-framework plugin

The framework rules (agent table, routing, command execution, model tiering, effort, fix rounds, memory, gate order) live in `POLICY.md`. This repository's `CLAUDE.md` holds the marker above, so the plugin does not print `POLICY.md` a second time, and carries only what developing the framework needs.

## Registry, frontmatter and validators
- `claude.json` is the registry and the source of truth for each agent's tier. `scripts/validate-consistency.sh` keeps the registry and `agents/*.md` frontmatter in step; `scripts/generate-docs.sh --check` verifies the generated README footer block.
- `omitClaudeMd: true` on every agent means sub-agents never see this file; the delegation brief's `Project rules` block is their only carrier.
- Every agent carries `disallowedTools` with `Artifact`; all but `system-architect` also deny `Agent`. The executors (`bash-expert`, `powershell-expert`) carry `Agent, Artifact`, a denylist: every tool except those two. `peer-review-critic` and `spec-compliance-reviewer` use curated `tools:` allowlists that omit Agent and merged `Agent, Artifact` into their existing deny list, plus the Read, Write and Edit the memory feature adds for their memory directory only; the code or spec under review is never theirs to change. `scripts/validate-consistency.sh` check 15 enforces `omitClaudeMd`, the `Artifact` denial and the `Agent` denial.
- Effort tiers live in each agent's frontmatter: reviewers `high`, implementers `medium`, executors `low`.

## Model-guard hook
`pretooluse-model-guard` (`PreToolUse` on `Task|Agent`) needs no configuration. On a POSIX host it needs `jq` in PATH; without it the hook fires and enforces nothing, like every hook here. It denies a sub-agent call whose `model` names the top tier (`fable`, in any spelling or as a full model id), denies every `fork`, denies opus in any spelling for the executors (`bash-expert`, `powershell-expert`, capped at sonnet), and rewrites a built-in agent call that carries no `model`: it sets `haiku` for `Explore` and `sonnet` for `Plan`, `general-purpose` and `claude`, then lets the call proceed. A plugin cannot ship an environment variable, so the hook does the floor's job for the agent types it recognises. `AF_MODEL_GUARD=off` disables it.

`CLAUDE_CODE_SUBAGENT_MODEL=sonnet` in the user's Claude Code settings `env` is an optional floor for any agent without a tier. The hook is not a general ceiling: an agent type it does not know (the user's own, or another plugin's) is neither denied nor rewritten, because the hook cannot read that agent's frontmatter; if that definition has no `model:` it inherits the caller's tier, and this variable is the only cover. When the variable holds a usable tier (non-empty, not naming the top tier), the hook leaves built-in calls alone and the variable decides.

## Releases
- User-visible changes to shipped plugin content (agents, commands, skills, hooks, `.mcp.json`, `settings.template.json`) need a version bump in both manifests, or installed users never receive them. Details are in `CONTRIBUTING.md`.
- The consistency and plugin-manifests suites build per-case copies from `git ls-files`: stage new files before running them. Run only the suites the change feeds.
- A release is a merged PR, a tag `vX.Y.Z`, and a GitHub release; the host plugin update and a restart follow.

## Gates (mechanics)
The order is in `POLICY.md`. Both gates below are enforced by hooks shipped in `hooks/hooks.json`.

**`peer-review-critic` is the mandatory final gatekeeper.** Before declaring any coding task done, run it as the last step — *after* `code-review-gatekeeper` and after the change is committed — to get an independent, diff-scoped critical review (branch vs base) and resolve every BLOCKER/MAJOR finding (or obtain explicit user sign-off). If its fix commits move HEAD, run `code-review-gatekeeper` again on the final HEAD before `gh pr create` or a push to `main`: the push/PR gate binds its approval to HEAD, so a gatekeeper run recorded before those commits no longer unlocks it.

This is enforced by a real Claude Code `Stop` hook: `hooks/stop-peer-review-gate.ps1` and `hooks/stop-peer-review-gate.sh`, shipped with the **agentic-framework plugin** via `hooks/hooks.json` as a shell-form dispatch chain (`sh dispatch.sh <name> || pwsh -NoProfile -File <name>.ps1`) with `${CLAUDE_PLUGIN_ROOT}` variable substitution — on POSIX hosts the .sh implementations require `jq` to parse their event JSON payload; without jq they fire but enforce nothing — the Stop gate and the push/PR gate are disarmed. Windows runs the .ps1 via pwsh (which uses ConvertFrom-Json), or the .sh under Git Bash when jq is available. It blocks ending a session when the current feature branch has committed work ahead of its base and the latest `peer-review-critic` run this session did not record `VERDICT: APPROVED` — a companion recorder hook (`hooks/record-subagent-run.ps1` and `.sh`, on `PostToolUse` and `SubagentStop`) parses the review's machine-readable verdict line into a per-session marker, reading the report from the stop payload's `last_assistant_message` or, when the harness delivers the report through the `SubagentHandback` tool (observed on Claude Code 2.1.303 to 2.1.308), from the sub-agent transcript's hand-back message; a PostToolUse launch acknowledgement (the Agent tool returns at launch) records nothing. The recorder accepts bare and plugin-scoped reviewer names. The gate is loop-safe (respects `stop_hook_active`), fail-open on any error (a marker without a parseable verdict unlocks it), and blocks a bounded number of times per session: once when no review ran, up to 3 times total while the verdict is `CHANGES_REQUIRED`. The recorder is hardened against stale re-emissions: repeat stops of the same reviewer instance, and id-less APPROVED-over-CHANGES_REQUIRED flips, are ignored unless HEAD has moved — on the id-less path escalation to CHANGES_REQUIRED always records — and every suppression is logged beside the marker, with all failure paths falling back to last-write-wins.

**The push/PR gate** (`hooks/pretooluse-code-review-gate.ps1` and `.sh`, `PreToolUse` on the shell tools) allows a push or a PR/MR creation only as a plain single command with literal names (`git push [options] [<remote> [<refspec>]]`, `gh pr create` or its alias `gh pr new`, `glab mr create` or its alias `glab mr new`, optionally after one location form (`cd <dir> &&`, `cd <dir>;`, PowerShell `Set-Location <dir>;`) or as `git -C <dir> push ...`) and denies every other command that mentions one, chains included, asking for it to be split into plain commands. A plain push's destination is resolved the way git resolves it (explicit refspec, `remote.<r>.push`, `push.default`, upstream); a push whose destination is `main` or `master`, and every PR/MR creation, is held until a `code-review-gatekeeper` sub-agent run applying `agentic-framework:code-review` has recorded `VERDICT: APPROVED` for that destination, whose marker's `head=` equals the current HEAD and whose `Target:` range `(<merge-base>..<head-sha>)` ends at the current HEAD and starts at a merge-base that is an ancestor of the destination, so the approval is bound to the reviewed commits, not to the HEAD at record time alone. `record-subagent-run` writes that record to `code-review/<session>` and the gate reads it from there. The gate stacks on the Stop gate with no cross-unlock: a `peer-review-critic` APPROVED never satisfies it, and a gatekeeper APPROVED never satisfies the Stop gate. It is a best-effort guardrail over direct Bash and PowerShell commands, not a sandbox. Its limitations are: scripts, aliases, `gh api`, shell-capable tools outside the matcher, forged local state (a remote-tracking ref, the marker file or the sub-agent transcript the recorder reads), hosts slower than the 8 s budget, git older than 2.31, SHA-256 repositories, a host without `jq` on the POSIX path, escape sequences or string building inside a command word, and a `CDPATH` that redirects a relative `cd` (decision N of the spec); the executor agents' no-push rule and the Stop gate remain the other layers. Git older than 2.31 and a SHA-256 repository fail closed (a deny). POSIX hosts need `jq`, plus the base utilities `tr`, `sed -E` and `grep -a -E`. `AF_CODE_REVIEW_GATE=off` in the launch environment (a restart is needed to pick it up) is the only sanctioned bypass. The gate guards against a review that was skipped or forgotten in an ordinary session, not against a model that deliberately evades it by forging the local state it reads (a remote-tracking ref, the marker file or the sub-agent transcript the recorder reads), which is outside its model exactly as it is for the Stop gate.
